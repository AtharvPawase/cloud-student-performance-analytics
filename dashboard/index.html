    How this dashboard gets its numbers

    The same five stages run in the cloud every time a teacher saves a mark.

    Stage 1Data collection

    Teachers enter marks and attendance in a web form; the exam section can upload a CSV. Every entry is checked for range and duplicates before it is accepted.

    Stage 2Cloud storage

    Validated records are written through a REST API to a managed cloud database holding students, subjects, marks and attendance tables.

    Stage 3Cloud processing

    A serverless function triggers on every write, cleans the record and recalculates averages, pass status and subject summaries.

    Stage 4Real-time delivery

    The summary tables are published on a live channel. The dashboard subscribes to it, so a saved mark reaches the screen in a few seconds without a page reload.

    Stage 5Visualisation

    The browser applies the selected filters, recomputes the KPIs and redraws every chart and table from the updated summaries.

    Demonstration dataset: 90 students · 6 subjects · 6 assessment months. Figures are simulated for a college field project. Pass mark 40 · attendance warning below 75%
